# 首页怎么写、样式与构造怎么改

**什么时候读它**：你在排首页（顶栏栏位、下拉菜单、纯链接节），
或者要把站点换成自己的配色 / 字号，要加一块**新构造**（图片、折叠、卡片…）。

## 一、首页就是一份 skill（有它自己的规矩）

| 你写的 | 站点上变成 |
|---|---|
| H1（`# 标题`） | **站名**（顶栏左边）+ 首屏大标题；它**不进正文** |
| 首个 `##` 之前的段落 | 首屏引言（`lede`） |
| 每个 `##` | 顶栏**一条栏位** —— 点了换正文里的那一节 |
| `###` / `####` | 留在那一栏的正文里（不再是栏位） |
| `## [名字](目标)` | **纯链接节**：点那一栏**直接渲染目标文件** |
| 某个 `##` 底下**整条是链接的列表** | 那一栏的**下拉菜单**（悬停出 / 触摸点开展开） |

三条会咬人的（都吃过）：

- **栏名要短**：顶栏是**一行**（左边站名、右边一排分段控件），7 个长标题会把它挤爆。
  细则放正文第一句，别写进标题。
- **纯链接节的判定很严**：只有 `[名字](目标)` 占满**整条标题**才算；正文里有链接**不算**。
  目标是相对**首页那份 skill 的目录**解析的，**认不出来就报错**（不给你一个静默的死链）。
- 纯链接节如果**还带着正文**，生成器会提示"点它会跳到 X"—— 那条正文只在"不跳"时才看得到，
  想让它真的显示就别把标题写成链接。

## 二、markdown 支持的构造（刻意窄）

正文块：标题（`###`/`####`）、段落、列表、表格、围栏代码块、引用、分隔线。
行内只认三样：`` `code` ``、`**bold**`、链接。

两条刻意的边界：

- **不认识的构造逐条点名报错**（图片、原始 HTML…），**不静默丢内容** ——
  "解不开的必须看得见"；生成器报错时 `--check` 也一起红。
- **链接按"台词"渲染**（这是静态阅读页，没有路由）：文字与目标相同时只留一份；
  否则渲染成"文字 + 代码样式的路径"。

要加**图片 / 折叠 / 卡片**这类新构造：解析边界与渲染是**两边**的事，见第四节。

## 三、改外观：配色、字号、代码颜色

配色与字号都在站点应用的 `app.mbt` 里（文件顶部一组常量，改这里就换皮）：

| 常量 | 管什么 |
|---|---|
| `c_bg` / `c_card` / `c_side` | 纸色底 / 卡片 / 文档区侧栏 |
| `c_ink` / `c_ink2` / `c_ink3` | 正文三级字色 |
| `c_accent` | 强调色（引用竖线、选中态） |
| `c_line` / `c_code` | 分隔线 / 行内代码底色 |
| `c_head` / `c_head_ink` / `c_head_ink2` / `c_head_on` | 顶栏底色 / 顶栏字色 / 次级字色 / 选中块 |

字号在各处的 `font_size`（正文 ~14、栏目标题 ~17.5、H3 ~15、H4/小字 ~13.5）；
标题、正文、引用、表格、代码块分别有自己的视图函数，改一处只影响那一类。

**代码块的颜色是另一条链**：色号（`PALETTE` 的索引）由程序 `lib/highlight.mjs` 决定，
而"这个色号长什么样"由 `app.mbt` 的 `tok_color` 决定 —— **索引两边对齐，改要一起改**，
错位不会报错，只是颜色悄悄变了。

⚠️ 样式层的坑（改样式前值得知道）：这套界面是 moobile 的样式系统，
RN 上有几条"写了不报错但没效果"的陷阱（按下一类、`transform` 每项只读第一个键、
`position: sticky` 连构造器都没有、`View` 不滚动）。这些的家是内容仓的那份
`skills/moobile-pitfalls/`，别在这儿重抄。

## 四、加一块新构造 = 两边一起改

| 这边 | 改什么 |
|---|---|
| 程序侧 `lib/gen-content.mjs` | 解析：把 markdown 里的新写法变成类型化数据（`Block` / `Span` 的新分支） |
| 实例侧 `app.mbt` | 渲染：`block_view` 里给新分支写画法（现成 8 种：标题三档 / 段落 / 引用 / 代码块 / 列表 / 表格 / 分隔线） |

只改一边的症状：解析出来了但页面不显示（`match` 穷尽性会提醒 app 侧），
或者渲染没数据可渲。**生成物是两边共用的契约**（`content/content.generated.mbt`），
所以改完必须 `press` 重生成，然后 `verify` —— 站点判据里"渲染出来的与内容源逐字一致"那条会盯着。

## 五、改完的验收

```bash
node ../skillpress/bin/skillpress.mjs press --check   # 内容源与生成物一致
node ../skillpress/bin/skillpress.mjs audit           # 上色的闸门（改配色/色号后必跑）
```

实例里 `npm run build` → `npm run serve` 看效果；要机器判据就跑 `verify`
（它要求 `dist/bundle.js` 已经在，见 `references/make-a-site.md`）。

⚠️ **别手改生成物**（`content/content.generated.mbt`）：它的新鲜度由 `press --check` 保证，
手改之后下一次 `press` 就把你那次改动抹掉，而你会先经历一段"改了没反应"的困惑。
