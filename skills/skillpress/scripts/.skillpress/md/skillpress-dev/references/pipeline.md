# 站点管线内部

**什么时候读它**：你要动内容管线（`engine/content/`）、动上色（`engine/highlight/`）、
加一条站点判据（`engine/site/checks.mbt`），或者遇到「改了内容源但站点没变」。

## 一、数据形状（内容包只有数据，渲染在应用里）

`gen-content.mjs` 把 markdown 编成**站点应用**的 `content/content.generated.mbt`（**生成物，别手改**）：

| 类型 | 是什么 |
|---|---|
| `Span` | 一段行内内容：`Txt` / `Code` / `Bold`（行内只认这三种写法） |
| `Block` | 正文里的一块：标题 / 段落 / 列表 / 表格 / 代码块 / 引用 / 分隔线 |
| `Code(lang, text, runs)` | 代码块 + **高亮片段**；`runs` 拼回去要**逐字节等于** `text` |
| `Section` | 首页的一个**分栏** = 首页那份 skill 的一个 `##`（`title` + `blocks` + `link`） |
| `Home` | 首页：`title`（H1）+ `lede`（首个 `##` 之前）+ `sections` |
| `Kid` | 子页：某份 skill 的 `references/**`、`FAQ.md`、或它的脚本文件 |
| `Doc` | 一份 skill：`slug` / `desc` / `when` / `blocks` / `kids` |

三个入口：`home()`（首页）、`skills()`（文档区，按 slug 排序 ⇒ 生成物稳定）、
`find_page(key)`（页面键 → 位置，给纯链接节用；认不出给"没有"）。

⚠️ **页面键的形状在生成器与生成物两侧各写一次**（主文档 = `<slug>`、子页 = `<slug>/<kind>/<name>`），
改一边必须改另一边 —— 它们靠那段注释对账。

## 二、markdown 的解析边界（刻意的窄）

只支持内容源里**实际用到的**构造；遇到不认识的（图片、原始 HTML…）**逐条点名报错**，
不静默丢内容。三条会咬人的：

- **`#` 不进正文**：H1 被抽成 `title`（站名 + 首屏大标题）。
- **`##` 就是分栏边界**：顶栏有几条完全由首页那份 skill 决定 ⇒ 它的 `##` 必须写**短名**。
- **链接按"台词"渲染**（没有路由）：文字与目标相同时只留一份，否则渲染成"文字 + 路径"。
- ⚠️ **解不开的东西是硬错误，不是跳过**：未闭合的代码块 / 图片 / 原始 HTML / 表格缺分隔行 ——
  生成器直接**非零退出**（不肯产出一份"看着像样"的产物）。所以那类用例**进不了对账夹具**；
  这是**刻意**的，别改成静默跳过（内容写坏了要当场拦住）。

### 纯链接节：`## [名字](目标)`

节的标题**整条是一个链接**时，点那一栏**直接渲染目标文件**：
生成期把目标按"首页那份 skill 的目录"解析成**页面键**写进 `Section.link`，
**认不出来就报错**（不给静默的死链）；应用侧再把键换成"跳到那一页"的消息，
换不出来就退回普通分栏。判定刻意严：正文里有链接**不算**。

## 三、两种模式（状态机很小，两条通道别混）

`Model` 四个字段：`mode`（0 = 首页，1 = 文档）、`sec`（首页选中第几栏，`-1` = 首屏）、
`sel`（文档区选中的页）、`open`（树里哪几份 skill 展开着）。消息四类：
顶栏分栏 / 换模式那条 / 文档区的页（skill、子页、纯链接节都走它）/ 树上的展开箭头。

⚠️ 顶栏那条**换模式的栏位和别的分栏长得一样**（D2：它只是最右那一栏，差一条竖细线），
但**标签要它自己的名字** —— 曾经它落进了 `i < 0 ⇒ "首页"` 的兜里，
于是顶栏出现两条「首页」、`文档 / SKILL` 一次都没出现，而判据点了错的那条
（真因与代价见内容仓的 `../moobile/docs/FINDINGS.md` 第三十二轮）。

## 四、上色（构建期，tree-sitter）

形状：`engine/highlight/`（引擎）+ `grammars`（vendor 的 wasm 与 `highlights.scm`，
出处与 sha256 见那份 `PROVENANCE.md`）。`web-tree-sitter` 是这台引擎**唯一**的 npm 依赖。

两条硬规矩：

- **色号两头对齐**：`PALETTE` ↔ 站点应用的 `tok_color`，改要一起改（错位不报错，只是颜色变了）。
- **拼回原文**：颜色逐字符贴，`highlight()` 硬断言"拼回去逐字节等于原文"，否则抛错。

**片段是常态 ⇒ 有"包装候选"**：文档里的代码块大多不是合法代码（顶层裸表达式最常见），
tree-sitter 会给出 ERROR 节点，而 **ERROR 里的东西一个 capture 都拿不到**。
解法是每种包装试一遍（函数体 / let 绑定 / 调用参数 / 数组元素 / struct 字段 / match 分支…），
取"未上色的非空白字符最少"的那个。

⚠️ **一个安静得可怕的坑**：tree-sitter 的 `Parser` 是**有状态**的 —— 按需加载语言时只
`setLanguage` 一次，于是"最后装载的语言"会污染之后所有解析（页面照常渲染，只是颜色少了）。
**每种语言一个 `Parser`**。

闸门是 `audit`：用纯正则数出"必须上色的词法元素"，报召回率与漏色比例，越线即红
（要准数就跑一遍）。

## 五、站点判据怎么加一条（`engine/site/checks.mbt`）

判据清单的**家是那个脚本的文件头**（一张表：每条断言抓哪个失败模式）—— 加之前先读它。

几条硬规矩（都是踩出来的）：

- 点击一律走 **CDP 真鼠标**：`Pressable` 在 web 上走 responder 事件，合成 `click()` 不一定触发
  —— 那样判据会变成**永远绿**。
- **端口动态挑**：写死端口会撞上"机器上已经有一个同端口在跑"，于是判据测的是**别人那个服务**。
- **Chrome 的 stderr 必须留着**：CDP 连不上时，真正的原因只在 Chrome 自己的话里。
- **探针文字从内容源现算**（首页从那份 SKILL.md 取、skill 从 frontmatter 取），不写死在脚本里。
- **同一次运行里的两处口径必须一致**：一处用"整页子串"、另一处用"元素整条文本"时，
  前者会**假绿**并把真 bug 藏起来（实测代价：顶栏标签写错 + 3 条判据被静默跳过）。
- **"找不到元素"不许退化成跳过**：`总数`也是读数 —— 跳过的形状与通过一模一样，
  只有写下总数、并与上一次对，才看得见。
- 区分"做了"与"没做"：只验"渲出来了"抓不到"点了没反应"。

## 六、生成物的新鲜度

- `press` 写生成物；`press --check` 是门（不一致即红，并指出**第一处差异**）。
- **别手改生成物**：下一次 `press` 会抹掉，而你会先经历一段"改了没反应"。
- 实例要能**独立编译**：生成物要进仓库（它不是可以随时重造的缓存）。

已知边界（别当成已覆盖）：没配语法的标记按原文渲染（`LANGS` 加一行即可支持）；
fence 标错语言会**染错**而不是报错（那要改**家**，不是改投影）；
锚点 / 目录 / 搜索还没做（语法树已经在手上）。
